pi0.5 × LIBERO × embodiment

Untouched pi0.5 base weights and pi0.5-LIBERO evaluated with the default Panda, fixed-base RBY1 right arm, and UR5e + Robotiq 85. UR5 tests whether a more similar tabletop industrial-arm setup recovers behavior without model finetuning.

Scope: this is a one-initial-state diagnostic slice, not the official 50-state LIBERO score. RBY1 and UR5 are non-official cross-embodiment evaluations and are reported separately from Panda. The base UR5 Pro run is explicitly partial.

RBY1 failure mode

The gripper works; transfer does not

All 50 pi0.5-LIBERO RBY1 failures timed out at 280 steps. The controller, arm, and jaw were active, so a frozen or incorrectly shaped gripper is not a sufficient explanation.

Observed controller evidence

Across the 10 normal RBY1 episodes, the arm travels meaningful distances and repeatedly commands the gripper closed. Videos show near-object reaching and premature basket motion, but no robust pre-grasp and pickup.

Interpretation: the dominant gap is Panda-to-RBY1 viewpoint, proprioceptive state, pre-grasp geometry, and action-dynamics transfer—not absent jaw actuation.

UR5e + Robotiq 85 control

The closer setup does better

UR5 recovers 6/50 successes from the same pi0.5-LIBERO checkpoint that scored 0/50 on RBY1. This supports the similarity hypothesis, while the 32/50 Panda result shows a large remaining embodiment gap.

Native robot and gripper physics

The adapter uses robosuite 1.4's native UR5e and stock Robotiq 85 geometry, joints, actuator, and contact model. Only gripper speed is set to 0.2 to match the Panda binary-gripper response time. The model still receives the same 8-D LIBERO state contract.

Independent proof: the scripted controller grasps salad dressing, lifts it, transports it, and releases it in the basket in 210/280 actions.

Reproduction

Run the recorded protocol

Run from the repository root. Each model server stays live while four benchmark clients run concurrently. The model samples stochastically, so the protocol and artifacts reproduce; individual binary outcomes need not.

1. Build the cross-embodiment images
docker/build.sh libero_rby1
docker/build.sh libero_pro_rby1
docker/build.sh libero_ur5
docker/build.sh libero_pro_ur5
2. Start the pi0.5 base server
UV_CACHE_DIR=/tmp/uv-cache uv run --no-sync vla-eval serve \
  -c configs/model_servers/pi0/libero_base.yaml -v
3. Run the four evaluation cells concurrently
RERUN_ROOT=results/matrix_rby1_fixed_reproduction
RERUN_MODEL=pi05_base

uv run --no-sync vla-eval run -c configs/benchmarks/libero/object.yaml \
  --shard-id 0 --num-shards 50 --eval-id rerun-rby1fix-${RERUN_MODEL}-panda-normal-e0 \
  --output-dir ${RERUN_ROOT}/${RERUN_MODEL}/panda_normal --record-video -y -v &
uv run --no-sync vla-eval run -c configs/benchmarks/libero_rby1/object.yaml \
  --shard-id 0 --num-shards 50 --eval-id rerun-rby1fix-${RERUN_MODEL}-rby1-normal-e0 \
  --output-dir ${RERUN_ROOT}/${RERUN_MODEL}/rby1_normal --record-video -y -v &
uv run --no-sync vla-eval run -c configs/benchmarks/libero_pro/object.yaml \
  --shard-id 0 --num-shards 50 --eval-id rerun-rby1fix-${RERUN_MODEL}-panda-pro-e0 \
  --output-dir ${RERUN_ROOT}/${RERUN_MODEL}/panda_pro --record-video -y -v &
uv run --no-sync vla-eval run -c configs/benchmarks/libero_pro_rby1/object.yaml \
  --shard-id 0 --num-shards 50 --eval-id rerun-rby1fix-${RERUN_MODEL}-rby1-pro-e0 \
  --output-dir ${RERUN_ROOT}/${RERUN_MODEL}/rby1_pro --record-video -y -v &
wait
4. Repeat with pi0.5-LIBERO

Stop the base server, start the fine-tuned server, set RERUN_MODEL=pi05_libero, and repeat the four commands above.

UV_CACHE_DIR=/tmp/uv-cache uv run --no-sync vla-eval serve \
  -c configs/model_servers/pi0/libero.yaml -v
5. Run UR5 normal and Pro
uv run --no-sync vla-eval run -c configs/benchmarks/libero_ur5/object.yaml \
  --shard-id 0 --num-shards 50 --eval-id ur5-${RERUN_MODEL}-normal-e0 \
  --output-dir results/matrix_ur5_reproduction/${RERUN_MODEL}/ur5_normal \
  --record-video -y -v

uv run --no-sync vla-eval run -c configs/benchmarks/libero_pro_ur5/object.yaml \
  --shard-id 0 --num-shards 50 --eval-id ur5-${RERUN_MODEL}-pro-e0 \
  --output-dir results/matrix_ur5_reproduction/${RERUN_MODEL}/ur5_pro \
  --record-video -y -v
6. Restore ownership and merge artifacts
docker run --rm -v "${PWD}/${RERUN_ROOT}:/data" --entrypoint chown \
  ghcr.io/allenai/vla-evaluation-harness/base:latest \
  -R "$(id -u):$(id -g)" /data

find ${RERUN_ROOT} -name 'recording-*.sqlite' -print0 \
  | xargs -0 -n1 uv run --no-sync vla-eval merge --db
